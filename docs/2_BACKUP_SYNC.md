# 2. Бэкапы и синхронизация

> **v1.3:** синхронизация переписана — см. `7_SYNC_SECURITY.md` (E2E, папка + Supabase). Ниже — описание бэкапов и слияния, оно актуально.

## Как хранятся данные сейчас
```
WebView2 / браузер
└─ localStorage
   ├─ focusday.data.v1        ← всё состояние (задачи, списки, XP, статистика) одним JSON
   ├─ focusday.snapshots.v1   ← до 8 точек восстановления (авто раз в день + перед импортом/откатом)
   └─ focusday.device         ← случайный ID этого ПК (для синхронизации)
```
В EXE это файлы в `%LOCALAPPDATA%\app.focusday.desktop\EBWebView\…`. Лимит ~5–10 МБ ≈ десятки тысяч задач.
Запись идёт с задержкой 120 мс и принудительно при закрытии/сворачивании окна.

## Модель данных для слияния (реализовано)
```js
task = { id: "t_m3x1_ab12cd",   // НИКОГДА не меняется: ни при импорте, ни при синхронизации
         updatedAt: 1730841600000, // ставится автоматически при любом изменении (diff-трекер в persist)
         xp: 42,                   // сколько XP уже выдано за задачу (анти-фарм)
         ...остальные поля }
data.deleted = { "t_old": 1730841000000 }  // tombstones: удалённые задачи не «воскреснут» из старого бэкапа (хранятся 120 дней)
```
Изменения отслеживаются **централизованно** в `persistNow() → trackChanges()`: сравнивается хэш каждой задачи с прошлым сохранением. Не нужно помнить про `updatedAt` в каждой функции.

## Экспорт (кнопка «Экспортировать бэкап»)
Файл `focusday-backup-2026-11-05_23-53.json`:
```json
{ "app": "Focusday", "schema": 3, "exportedAt": "2026-11-05T22:53:00Z",
  "device": "dev_m3x1_ab12cd", "counts": { "tasks": 128, "lists": 6, "achievements": 9 },
  "checksum": "2c83e946…",   // SHA-256 от data — ловит повреждённые/отредактированные файлы
  "data": { … } }
```
**Зашифрованный бэкап `.fdbak`:** AES-GCM-256, ключ из пароля через PBKDF2-SHA256 (310 000 итераций), случайные salt/iv. Всё в WebCrypto — без серверов и библиотек. Подходит для облаков и Telegram.

## Импорт: безопасный алгоритм
```
файл ─► readBackup()  ── .fdbak? → спросить пароль → расшифровать
          │             └─ проверить schema / tasks[] / SHA-256
          ▼
      mergeData(local, incoming) — ПРЕДПРОСМОТР: «+3 новых · 2 обновится · 120 без изменений · 1 удалена ранее»
          ▼
      пользователь выбирает:  [Объединить ✓]  или  [Заменить всё]
          ▼
      snapshot("Перед импортом") ─► применить ─► тост «Откатить» (1 клик)
```
Правила `mergeData` (last-write-wins):
| Ситуация | Результат |
|---|---|
| ID есть только в файле | добавить (если нет более нового tombstone) |
| ID есть в обоих | побеждает больший `updatedAt`; `xp` = max (XP не выдастся повторно) |
| Задача удалена позже, чем изменена | удалить |
| Дубликаты ID внутри файла | оставить самую свежую версию |
| Списки | объединение по `id`; потерянные списки восстанавливаются |
| Достижения | объединение множеств, даты — самые ранние |
| Статистика | по каждому счётчику max; тепловая карта — max по дню |

Поддерживаются старые бэкапы (v1 без `schema`/`checksum`) и «голый» JSON состояния.

## Точки восстановления
Настройки → «Точки восстановления…» → «Откатить». Создаются автоматически: раз в день, перед импортом, перед откатом. Хранятся 8 последних.

## Синхронизация между ПК — 3 варианта
| | **Папка в облаке** ✅ реализовано | Google Drive API | Telegram-бот |
|---|---|---|---|
| Сложность | минимальная | средняя (OAuth, ключи Google Cloud) | средняя (свой бот, хранение токена) |
| Сервер | не нужен | не нужен (appDataFolder) | не нужен, но API бота медленный и не для файлов-«баз» |
| Конфликты | merge по `updatedAt` | то же | то же |
| Приватность | файл зашифрован паролем | зашифрован | зашифрован, но лежит в чате |

**Реализовано в EXE:** Настройки → «Синхронизация через папку» → выбрать папку OneDrive / Google Drive для ПК / Dropbox / Syncthing → пароль.
```
ПК-1 ── изменение ─► через 15 с: encrypt(payload) ─► sync_write(dir, "focusday-sync.fdbak")  (атомарно tmp→rename)
                                                        │  облачный клиент разносит файл
ПК-2 ◄─ при запуске и при фокусе окна: sync_read ─► decrypt ─► mergeData ─► перерисовать
```
- Пароль хранится только в `sessionStorage` (спрашивается раз за запуск), на диск не пишется.
- Rust-команды `sync_write` / `sync_read` в `src-tauri/src/lib.rs` проверяют имя файла (без `..`, только безопасные символы).

**Google Drive (если захочешь без облачного клиента):** OAuth 2.0 «Desktop app» → scope `drive.appdata` → `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart` в `appDataFolder`. Провайдер реализует те же `read()/write()`, что `Sync` в `focusday.js` — остальной код не меняется.

**Telegram-бот:** `sendDocument` в свой чат (бэкап «в облако одной кнопкой») — отличный вариант для *ручных* бэкапов, но не для авто-синхронизации: получить последний файл можно только через историю апдейтов бота, которая хранится 24 ч.
