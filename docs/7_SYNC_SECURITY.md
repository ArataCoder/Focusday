# 7. Синхронизация ПК ⇄ телефон: безопасность и бесплатный хостинг

## Вердикт
**Безопасно — при условии хорошего пароля синхронизации.** Данные шифруются **на устройстве** до отправки (сквозное шифрование, E2E). Сервер (Supabase, Google Drive, iCloud — неважно) хранит только шифротекст и не может его прочитать: ни владелец сервера, ни Google, ни я как автор кода. Поэтому синхронизацию **не нужно убирать** — модель «сервер ничего не знает» закрывает требование «вижу только я».

## Как это устроено
1. Пароль синхронизации (≥ 10 символов, лучше фраза из 4–5 слов) → **PBKDF2-SHA256, 600 000 итераций** + случайная соль → ключ **AES-GCM-256**.
2. Ключ хранится в IndexedDB как **неизвлекаемый** `CryptoKey` — даже JS-код страницы не может его прочитать и отправить. Сам пароль нигде не сохраняется.
3. Весь дневник (задачи, привычки, финансы, мысли, цитаты) → JSON → AES-GCM (уникальный IV на каждую запись, AAD `focusday-vault-v2` — подмена байта ломает расшифровку).
4. В облако уходит конверт `{app, v, kdf:{alg, iter, salt}, iv, ct, at, device}`.
5. Слияние на устройстве: по id + `updatedAt` + «надгробия» удалённых. Конфликт двух устройств одновременно ловится ревизией (`rev`) — проигравший перечитывает, сливает и пишет снова. Ничего не теряется.
6. Пароль **аккаунта** Supabase (для входа) и пароль **синхронизации** (для шифра) — разные. Утечка первого не раскрывает данные.

**Риски, о которых честно:**
* Забыл пароль синхронизации → облачную копию не расшифрует никто. Данные на устройствах остаются, можно задать новый пароль и выгрузить заново.
* Слабый пароль («12345678») можно подобрать офлайн, если украдут шифротекст. Используй фразу: `кот-пьёт-какао-в-Аликанте`.
* Метаданные видны серверу: e-mail, время синхронизаций, примерный размер файла. Содержимое — нет.
* Заражённое устройство (кейлоггер) обходит любое шифрование — это вне модели угроз.

## Вариант 1 — облачная папка (EXE, ничего настраивать не надо)
Настройки → Синхронизация → пароль → «Папка: Выбрать» → папка внутри Google Drive / OneDrive / iCloud Drive / Dropbox.
Focusday пишет туда зашифрованный `focusday_data.json` (атомарно: tmp → rename). Второй ПК указывает ту же папку и тот же пароль.
Ограничение: телефон не умеет «смотреть» в папку Google Drive из приложения, поэтому для телефона — вариант 2.

## Вариант 2 — Supabase (ПК + телефон + браузер)
**Бесплатно для ≤ 20 человек с запасом:** Supabase Free — 500 МБ базы, 50 000 активных пользователей/мес, 5 ГБ трафика. Один дневник — 50–500 КБ. Минус: бесплатный проект **засыпает после 7 дней без запросов** (будится кнопкой Restore в панели; если хоть кто-то синхронизируется раз в неделю — не уснёт).

### Настройка (10 минут, один раз; друзья могут пользоваться твоим проектом — каждый видит только свой шифротекст)
1. supabase.com → New project (регион Frankfurt/EU).
2. **SQL Editor** → выполнить:
```sql
create table public.vaults (
  user_id    uuid primary key default auth.uid() references auth.users(id) on delete cascade,
  blob       text   not null,
  rev        bigint not null default 1,
  updated_at timestamptz not null default now()
);
alter table public.vaults enable row level security;

-- Каждый пользователь видит и меняет ТОЛЬКО свою строку
create policy "own vault read"   on public.vaults for select using (auth.uid() = user_id);
create policy "own vault insert" on public.vaults for insert with check (auth.uid() = user_id);
create policy "own vault update" on public.vaults for update using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own vault delete" on public.vaults for delete using (auth.uid() = user_id);

-- Защита от мусора: сейф не больше 5 МБ
alter table public.vaults add constraint blob_size check (octet_length(blob) < 5000000);
```
3. **Project Settings → API**: скопируй `Project URL` (`https://xxxx.supabase.co`) и `anon public` key. anon-ключ не секретный — без входа и RLS он ничего не даёт.
4. **Authentication → Providers → Email**: включён. Для своих можно выключить «Confirm email», иначе после «Создать аккаунт» придёт письмо.
5. В Focusday: Настройки → Синхронизация → пароль синхронизации → URL + anon key → e-mail + пароль аккаунта → «Создать аккаунт» (первый раз) / «Войти».
6. На телефоне то же самое с **тем же e-mail и тем же паролем синхронизации**.

Синхронизация: через 20 с после изменения, раз в 3 минуты, при возвращении в окно (если прошло > 1 мин) и кнопкой «Синхронизировать сейчас».

## Где разместить веб-версию (PWA для телефона) бесплатно
| Хостинг | Бесплатно | Комментарий |
|---|---|---|
| **Cloudflare Pages** | безлимит трафика, 500 сборок/мес | рекомендую: быстро в Испании/Европе, HTTPS, свой домен |
| GitHub Pages | 100 ГБ/мес | проще всего, если код уже на GitHub |
| Netlify / Vercel | 100 ГБ/мес | тоже ок |
Публикуется только папка `src/` (статичные файлы). Данные пользователей там не хранятся — только код приложения.

Альтернатива Supabase на будущее: Cloudflare Workers + KV/D1 (бесплатно 100 000 запросов/день) — тот же формат конверта, коннектор пишется за вечер.

## Проверено автотестами
* шифр/дешифр, неверный пароль → отказ, подмена 1 бита → отказ, короткий пароль → отказ;
* Supabase-коннектор на mock: вход, первая запись, оптимистичная блокировка ревизий;
* E2E: два «устройства» (ПК и телефон) через фальшивый Supabase — обе стороны получили данные друг друга, на сервере нет открытого текста, пароль синхронизации не уходил в сеть.
Реальный Supabase в песочнице не проверялся (нет доступа) — после настройки нажми «Синхронизировать сейчас» и проверь статус «🔒 E2E».
